# app.asr

离线日语识别里**贴着引擎和设备的**那一半：模型在磁盘上的位置、sherpa-onnx 的
装载与释放、把队列抽干的那个循环。「什么时候识别、识别几次」在 `core.asr`，
因为那半边能在 JVM 上测，这半边不能。

由 **Task45** 建立，决策见 `docs/ADR/ADR-012-ASR-Reinstated.md`。默认关闭。

## 三个文件各自的边界

- `AsrModel` —— 只有路径和「四个文件在不在」。**不做下载**，那是 Task46 的事。
  分开是因为 Task45 要能装载一个已经到位的模型：`adb push` 进去的，和将来下载
  进来的，对引擎是同一件东西。四个文件名保持上游原样——改名之后 ADR-012 里那
  几个摘要就不再描述磁盘上的东西了，而那些摘要是信任它的唯一理由。
- `SherpaRecognizer` —— `core.asr.SpeechRecognizer` 在 sherpa-onnx 上的实现。
  zipformer transducer，`numThreads = 1`，从**文件**而不是 assets 装载
  （`ADR-006 §2`：模型不打进 APK）。
- `TranscriptionWorker` —— 取文件、解码、识别、写回。刻意写薄：凡是能算规则的
  都在别处，循环体里的规则没人测得了。

## 不得阻塞 PTT，这条是怎么落实的

`§18.3` 无条件把语音排在识别之上。这里有两道检查，不是一道：

1. 循环每转一圈，开新的识别之前看 `SessionState`；
2. 解码完、真正调引擎之前**再看一次**——一条长录音的解码本身就够一通电话开始了。

任何一次撞上通话都走 `defer()`，**不扣重试次数**：活儿根本没跑过。

**不抢占。**已经在跑的那次识别会跑完。ADR-012 把耗时门槛定在「每秒音频不超过
一秒 CPU」，半路砍掉等于白烧已经花掉的 CPU，而那份工作还得重做。保证的是通话
期间不会**新开**识别，麦克风不跟模型抢一次新分配。

## 循环是睡着而不是退出

队列空了、或者被通话推迟，`drain()` 在一个 conflated channel 上等，不返回。
写过一版是 `return`——那会留下非空的 `loop`，于是之后每一次 `start()` 都成了空
操作：**第一个空闲时刻之后队列就再也不会被抽干**，而且不报错。唤醒有两个来源，
新录音入队和通话结束，后者由一个 `session` 的收集协程负责，所以「检查完通话状态
到睡下去」之间那个窗口不会丢唤醒。

## 模型用完就还

150 MB 常驻，设备只有 4 GB。队列空的时候 `release()`，第一次识别时再装。重装的
代价是一次没人等的文件读——识别本来就发生在通话**之后**，不在通话中间。
